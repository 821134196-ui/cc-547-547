# 装修工程结算台

验收后客户与项目经理核对**合同总价 / 已付款 / 整改尾款 / 质保金**的本地结算系统。
仅使用 Python 标准库（SQLite + http.server），支付与电子签名走**模拟适配器**，
现场照片存本地。

## 一条命令启动

```bash
python3 -m renovation            # 首次自动生成「部分验收」样例并打开浏览器
python3 -m renovation --no-browser --port 8000
python3 -m renovation --reseed   # 清掉样例数据重新生成
```

打开 http://127.0.0.1:8000/settlement ，右上角可切换身份（客户 / 现任 / 前任项目经理）。

## 领域规则（系统强制）

- **金额守恒**：合同价 = 已付 + 待双人签放 + 可付尾款 + 未验收留存 + 未结算工程款 + 质保金余额；
  金额一律以「分」存储，结算页实时校验并展示恒等式。
- **照片确认才放款**：整改项经理提交照片 → 客户逐条签认；**未验收 / 被打回项不计入可付金额**。
- **双人签放**：尾款与质保金需客户、项目经理各自确认；两人**同时或重复点击只产生一笔付款指令**
  （幂等键唯一 + 事务串行 + 网关去重）。
- **质保金隔离**：尾款永远不会误释放质保金；质保金须**到期且无未结索赔**才可结清，结清不可重复。
- **签署权限**：整改验收只能客户签（带模拟签名令牌），工程完成量只能现任项目经理录入，
  客户不能代录，经理不能自验，前任经理换人后失权。
- **回执可重放**：出账后银行回执可能延迟（可登记争议）；回执到达后重复查询幂等，不重复扣款。
- **依据留痕**：合同价调整保留全部旧版本，项目经理更换保留历任任期，争议、索赔、签认写入只追加事件流。

## 样例工程（部分验收）

合同 518,000 元（含一次 +18,000 调价）、质保金 25,000 元（2028-03-15 到期）：

| 整改项 | 状态 | 尾款留存 |
|---|---|---|
| R-01 主卧墙面裂纹 | 已验收通过 | 3,000 |
| R-02 厨房铰链 | 已验收通过 | 1,500 |
| R-03 次卫地漏找坡 | 已提交，**待客户确认照片** | 4,500 |
| R-04 阳台插座地线 | 首次被**打回·客户提出新问题**，待返工 | 2,500 |
| R-05 入户门补漆 | 待整改 | 1,000 |
| W-01 花洒渗水 | 质保返修（已处理，索赔已结） | — |

另有一笔质保索赔（窗台渗水）未结，用于演示质保金阻塞；一笔进度款回执延迟已立争议。

## 测试

```bash
python3 -m unittest discover -s tests
```

覆盖：金额守恒（全生命周期 + 调价）、质保到期与未结索赔限制、回执延迟与重放幂等、
签署/录入角色权限、两人并发只出一笔指令、未验收项不可付、尾款不吞质保金。

## 目录

```
renovation/
  db.py         SQLite schema（账务 + 版本/事件流）
  money.py      元/分换算
  adapters.py   模拟支付网关（幂等/回执延迟）与模拟签名
  service.py    领域服务与全部不变量
  seed.py       部分验收样例 + 本地 SVG 现场照片
  web.py        结算页（白 / 深灰 / 工程橙，手机端金额整行可见）
tests/          19 个规则测试
```
