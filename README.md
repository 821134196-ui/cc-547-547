# 装修工程结算系统

竣工验收后，客户与项目经理核对合同总价、已付款、保留质保金与未完成整改项。
整改照片经客户确认签认后才能申请释放对应尾款；质保金在约定期满且无未结索赔时另行结清。

纯 Python 标准库实现：SQLite 存账务与版本流水，照片存本地，支付与电子签名使用模拟适配器。

## 启动

```bash
./start.sh            # 等价于 python3 -m app，默认 http://127.0.0.1:8000
./start.sh --reseed   # 清空并重建“部分验收”样例数据
PORT=9000 ./start.sh
```

首次启动自动生成样例项目（含样例现场照片）。右上角可切换当前操作人（客户 / 项目经理），
服务端按角色鉴权——切换身份即可看到不同操作按钮与权限拦截。

## 样例场景（部分验收）

合同 192,000 元 + 增项 8,000 元（签证单依据）＝ 200,000 元；质保金 5%＝10,000 元。

- 进度款两笔合计 130,000；
- 整改①「阳台找平返工」已签认、尾款 10,000 已放款，**回执延迟在途**（可在“尾款申请”页触发“延迟回执到达”与“回执重放”）；
- 整改②「主卧墙面开裂」已签认，尾款 15,000 **待申请**；
- 整改②b「书房漏保」已提交照片，**待客户签认**（8,000）；
- 整改③「卫生间渗水」签认后客户**追加新问题**，父项尾款 20,000 暂缓；
- 整改④「橱柜门缝」尚未整改（5,000）；另有 2,000 元尾差；
- 质保期内有一笔未结返修；存在一条开放争议；
- 项目经理已从赵强更换为陈晨（留依据）。

## 页面

- **工程结算**：合同金额 / 已付 / 尾款 / 质保金四张卡片并列，下方守恒核对行
  （已付＋在途回执＋可付尾款＋待处理＋尾差＋质保金留存＝合同金额）。
- **整改清单**：逐条展开整改照片、提交/签认时间、签名令牌与核验结果。
- **尾款申请**：仅列出“已签认且无未结新问题”的整改项；勾选生成**一笔**付款指令；
  可模拟回执延迟、重放与到达确认。
- **质保金到期**：未到期或有未结返修/索赔时禁止结清；索赔从质保金扣减。
- **争议与依据**：争议、合同价调整、项目经理更换、完成量录入、只增不改的版本流水。

配色为白、深灰与有限的工程橙（仅用于待处理项与主操作）；手机端金额保持整行可见。

## 关键规则

1. 金额一律以“分”整数存储；结算视图内置守恒断言。
2. 未签认 / 有未结新问题的整改项不得计入可付金额。
3. 非质保付款（进度款＋整改尾款）上限为合同价－质保金，质保金不会被尾款误释放。
4. 客户不能代项目经理录入完成量；经理不能自签整改；更换经理仅客户可发起。
5. 同一组整改项并发重复放款：幂等键 + `BEGIN IMMEDIATE`，只产生一笔付款指令。
6. 支付适配器以申请单为幂等键：回执重放返回同一回执号，绝不重复出款。
7. 合同价调整、经理更换、争议、新问题均强制留存原因与依据，写入只增不改的 `event_log`。

## 测试

```bash
python3 -m unittest discover -s tests -v   # 24 个用例
```

覆盖：金额守恒（放款 / 回执到账 / 合同调整后）、质保金到期限制与索赔扣减、
回执延迟-重放-到达幂等、签署与录入权限、并发放款去重、未验收项不可付。
